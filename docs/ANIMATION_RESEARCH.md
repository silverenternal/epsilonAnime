# ASCII animation research — October 2026

The cinematic redesign was informed by recently active open-source terminal
animation projects. These repositories were cloned and inspected as references;
their source code is not vendored.

## Spatial follow-up (2026-10-24)

The numeric surface is now evaluated at the terminal's 2×4 braille subpixel
grid rather than the character grid. This doubles horizontal and quadruples
vertical sampling for stateful and 3D scenes without changing the display
cell count.

3D work uses the existing `glam` camera implementation. Curves are rasterized
as depth-weighted anti-aliased line segments, not isolated projected points.
Möbius and spherical-harmonic surfaces use two parameter directions; Lorenz
connects successive system states. The Klein bottle uses its standard
three-dimensional immersion, while the Hopf mode stereographically projects
points from S3 with a selected fiber family.

The 3D surface's high-frequency deformation is generated by the existing
`math_kernel!` proc macro, preserving the project's compile-time function
generation rather than hard-coding a second shader language.

Spatial brightness is also generated: `generated_orbital_light` maps camera
depth, view angle, and beat time to a normalized light response. The renderer
consumes that generated `FieldSample.light` value instead of an unrelated
hard-coded depth gain. This keeps the 3D shading curve and surface deformation
in the same inspectable generation layer.

Scene cadence is phrase-based: a new lyric hash may select a new skeleton at
four-line boundaries, while line progress and live spectral features continue
to animate inside the phrase. Trail decay is integrated with frame `dt`, so
frame rate changes do not alter apparent speed.

## Window compositing

The terminal cell buffer now provides a compositing primitive for floating
windows. An overlapping upper window mixes its tinted surface with the existing
cell background at 0.8 opacity; the previous foreground is pulled toward that
surface, leaving a faint 20% trace of the layer below. Deterministic per-cell
grain supplies a frosted texture without adding frame-to-frame flicker.

Glass is selected from actual z-order and rectangle intersection. A lower
window remains opaque until another window covers it, so overlapping surfaces
do not accidentally become two stacked semi-transparent quads.

## Resulting visual system

The default `cinematic` preset is a three-movement director:

1. **Aurora** — 16 spectral bands bend flowing ribbons; cover luminance is used
   as texture, not as a detached wallpaper.
2. **Orbit** — cover colours and luminance form a central nebula; tilted orbital
   rings, rotating sparks, and lyric shockwaves provide depth.
3. **Tide** — layered noise and spectral currents shape a shoreline-like field,
   with line changes cutting a transient wave.
4. **Bloom** — angular spectral harmonics expand into rhythmically breathing
   petals, recalling fireworks/halo compositions from the reference projects.

The cover worker extracts a per-song palette. The director receives spectral
bands, lyric index/progress/change pulses, and the cover image; transitions
between movements blend both live scenes. Raw mathematical presets remain
available as experimental "lab" modes, but they are no longer the default.

## Generated mathematics and cover particles

The final system also uses three stronger mathematical layers:

- OpenCV converts the cover into a salience/edge/luma-weighted point cloud.
  Rust particles assemble toward those targets with spring dynamics, BPM
  sub-beat motion and onset bursts.
- `specs/spectral_modes.toml` is compiled by `build.rs` into a 2D spectral basis,
  and `spectral_engine!` expands it into a sampled harmonic field.
- A complex polynomial potential drives an incompressible particle velocity
  through the conjugate of `dF/dz`; the director uses the same field to warp its
  Tide movement.

All temporal state is sampled at 32nd-note intervals derived from the measured
BPM rather than a fixed animation timestep. The final image uses percentile
auto-exposure before perceptual tone mapping, glyph selection and text contrast
repair.

## Hash-directed adaptive scenes

The default `adaptive` renderer hashes the current lyric line, title, artist and
quantised BPM with SHA-256. The digest selects exactly one of 12 mathematical
movements; only that scene is evaluated for the line. There is no four-scene
overlay and no cross-dissolve between two full scenes. A short exposure flash
marks the lyric cut.

The available modes are spectral synthesis, Julia, superformula, metaballs,
polar harmonics, complex flow, Newton fractal, projected torus knot, Fourier
epicycles, wave interference, Gray-Scott reaction diffusion and Clifford
attractor. Four spatial modes add a rotated Lorenz attractor, a Möbius strip,
a spherical-harmonic shell and a perspective-projected 3D wave surface.
Cinematic remains available as an optional curated preset.

Both cover particles and background animation sample at sub-character
resolution. Background cells use a 2x4 braille mask; cover cells use the same
subcell geometry with source RGB particle colors.

## Streaming features and danmaku

The PCM analyzer exposes spectral centroid, bandwidth/spread, flatness,
rolloff, zero-crossing rate, crest factor and stereo width in addition to
spectral bands. These parameters alter coordinates, harmonic order, domain
perturbation, torus perspective and complex velocity.

NetEase hot and recent comments are fetched alongside track metadata and cached
with the prefetched song. Rust launches them as danmaku on beat/onset/lyric
events. High-like comments receive a brighter palette accent. Danmaku is clipped
to a dedicated right-side rail with at most four active items and one shared
velocity model, avoiding full-screen clutter and refresh jitter.

To avoid turning subpixel detail into a wall of full braille cells, animation
coverage is now edge/highlight driven with a right-biased focus mask. This
preserves negative space while retaining 2x4 sub-cell sampling.

## Dedicated 2D spectrum view

The compact `SPECTRUM` panel is a draggable, independent spectrum display. It
stores a 24-frame history of the 16 bands and renders frequency horizontally
against time vertically as a braille heatmap. Its history cadence follows BPM.
The 2D form is more legible at terminal-cell resolution than the earlier 3D
mesh and leaves a separate rail for danmaku.
